Giữ nguyên tinh thần giao diện của bản v1 — thanh điều hướng tối màu, lưới bài viết dạng thẻ, gạch chân gradient hồng–vàng — trong khi bổ sung tài khoản người dùng, phân quyền theo vai trò, biên tập bài viết chuẩn SEO, hệ thống tải game trả phí bằng ví nội bộ $P, và nạp tiền tự động qua SePay.

01Tổng quan

v1 hiện là một site dạng WordPress: trang chủ liệt kê bài viết mới, trang chi tiết có sidebar tìm kiếm/bài viết mới/bình luận, đã có sẵn khái niệm "@CASH" trên thanh nav — cho thấy nhu cầu tiền tệ nội bộ đã tồn tại nhưng chưa được vận hành đầy đủ. v2 chuẩn hoá lại toàn bộ thành một hệ thống tự viết (custom build), giữ cảm giác quen thuộc cho người dùng cũ nhưng vận hành trên nền tảng có thể mở rộng: tài khoản, phân quyền chi tiết, biên tập nội dung chuyên nghiệp, và một hệ kinh tế nội bộ ($P) gắn với việc tải file.

Người dùng

Tài khoản & hồ sơ

Đăng ký, đăng nhập, quên mật khẩu, hồ sơ cá nhân, ví $P, lịch sử tải.

Nội dung

CMS chuẩn SEO

Soạn bài WYSIWYG, ảnh đại diện, danh mục, menu đa cấp kéo-thả, bình luận.

Kinh tế

Ví $P & tải file trả phí

Mỗi link tải gắn giá riêng, sinh presigned URL từ R2/S3, nạp tiền qua SePay.

03Đề xuất tech stack

Ưu tiên: tốc độ tải trang public (SEO-critical), toàn vẹn dữ liệu cho ví tiền (ACID), và chi phí hạ tầng hợp lý cho một site cộng đồng.

LớpLựa chọn đề xuấtLý do chọn / phương án thay thế
FrontendNext.js 15 (App Router) + TS + Tailwind + shadcn/uiSSR/ISR cho SEO & tốc độ hiển thị đầu tiên; React Server Components giảm JS gửi về client. Thay thế: Nuxt nếu team quen Vue.
Backend APINestJS (TypeScript)Module hoá theo domain (auth, wallet, posts, storage); Guard/Interceptor có sẵn rất hợp để chặn theo permission và ghi audit log giao dịch ví.
Cơ sở dữ liệuPostgreSQL 16 + Prisma ORMGiao dịch ACID bắt buộc khi trừ/cộng $P; JSONB cho metadata SEO linh hoạt theo từng bài viết.
Cache / Hàng đợiRedis + BullMQCache danh sách bài viết/danh mục nóng; queue xử lý webhook SePay và sinh presigned URL không chặn request chính.
Lưu trữ fileCloudflare R2 (chính) + AWS S3 (dự phòng)R2 miễn phí băng thông ra (egress) — quan trọng với file game dung lượng lớn; dùng chung SDK @aws-sdk/client-s3 vì cùng chuẩn S3 API. Trang cài đặt cho phép cấu hình nhiều bộ key song song.
Trình soạn thảoTiptap (ProseMirror)Headless, nhẹ, dễ nhúng upload ảnh/bảng/code block hơn CKEditor; kiểm soát HTML output để tránh XSS khi render lại.
Xác thựcJWT (access + refresh, cookie httpOnly) + Argon2Tự chủ hoàn toàn để khớp mô hình Role/Permission tuỳ biến, không lệ thuộc SaaS auth bên thứ ba.
Thanh toánSePay Webhook API (VietQR)Đối soát tự động theo nội dung chuyển khoản chứa mã giao dịch; xác thực chữ ký HMAC ở webhook.
SEOnext-seo · next-sitemap · JSON-LD · Open GraphSitemap tự sinh khi publish bài; snippet preview ngay trong trình soạn bài.
RealtimeWebSocket (Socket.IO)Đẩy số dư ví cập nhật tức thời sau khi SePay xác nhận, và trạng thái duyệt bài cho Moderator.
Hạ tầng & DeployDocker Compose + Caddy/Nginx, Cloudflare phía trướcCoolify/Dokploy trên VPS để CI/CD đơn giản, chi phí thấp — hợp quy mô site cộng đồng. Thay thế: Vercel (FE) + Railway/Fly.io (BE+DB) nếu muốn giảm việc vận hành.
Giám sátSentry · Uptime Kuma · Plausible/GA4Theo dõi lỗi, uptime và hành vi người dùng mà không kéo nặng trang public.
Kiểm thửVitest/Jest + PlaywrightBắt buộc test E2E cho 2 luồng trọng yếu: nạp tiền và tải game (ảnh hưởng trực tiếp doanh thu).

04Kiến trúc hệ thống

Cloudflare đứng trước để cache trang public và chống bot; backend tách khỏi frontend để cô lập logic nhạy cảm (ví, phân quyền, ký URL).

flowchart LR
  U["Người dùng"] --> CF["Cloudflare CDN / WAF"]
  CF --> WEB["Next.js — SSR/ISR Frontend"]
  WEB --> API["NestJS API"]
  API --> PG[("PostgreSQL")]
  API --> RD[("Redis — cache & queue")]
  API -- "presigned URL" --> R2[("Cloudflare R2")]
  API -- "presigned URL" --> S3[("AWS S3 (dự phòng)")]
  SEPAY["SePay"] -- "webhook nạp tiền" --> API
  API -- "realtime số dư" --> WEB
Frontend không bao giờ gọi trực tiếp R2/S3 hay SePay — mọi thao tác nhạy cảm (trừ tiền, ký URL, xác thực webhook) đi qua API để giữ tính toàn vẹn giao dịch.

05Luồng nghiệp vụ trọng yếu

Hai luồng ảnh hưởng trực tiếp đến tiền của người dùng — cần transaction chặt và chống trùng lặp webhook.

Tải game qua link trả phí UC11

sequenceDiagram
  actor U as Member
  participant W as Web App
  participant API as Backend API
  participant DB as PostgreSQL
  participant ST as R2 / S3
  U->>W: Bấm "Tải xuống" trên link #2
  W->>API: POST /downloads/:linkId
  API->>DB: Kiểm tra số dư ví $P
  alt Đủ số dư
    API->>DB: Trừ $P + ghi log giao dịch (1 transaction)
    API->>ST: Yêu cầu presigned URL (TTL 10 phút)
    ST-->>API: Signed URL
    API-->>W: Trả signed URL
    W-->>U: Chuyển hướng tải file
  else Không đủ số dư
    API-->>W: 402 — yêu cầu nạp thêm $P
    W-->>U: Hiển thị modal nạp tiền
  end

Nạp tiền tự động qua SePay UC09 · UC23

sequenceDiagram
  actor U as Người dùng
  participant W as Web App
  participant API as Backend API
  participant SP as SePay
  participant DB as PostgreSQL
  U->>W: Nhập số tiền muốn nạp
  W->>API: Tạo yêu cầu nạp tiền
  API->>DB: Lưu giao dịch trạng thái "pending"
  API-->>W: Trả mã QR VietQR (nội dung CK = mã giao dịch)
  U->>SP: Chuyển khoản theo QR
  SP->>API: Webhook xác nhận (kèm chữ ký HMAC)
  API->>API: Xác thực chữ ký & chống gọi trùng
  API->>DB: Cập nhật "success" + cộng $P vào ví
  API-->>W: Đẩy realtime số dư mới (WebSocket)
  W-->>U: Thông báo nạp tiền thành công
Chống trùng lặp: mỗi webhook lưu theo mã giao dịch SePay duy nhất (unique constraint) — webhook gọi lại nhiều lần không cộng tiền 2 lần.

06Mô hình phân quyền (RBAC)

Vai trò chỉ là một tập hợp quyền (many-to-many), không hard-code trong logic — nhờ vậy Admin có thể tạo Custom Role bất kỳ bằng cách tick các quyền mong muốn. Middleware luôn kiểm tra theo mã quyền (post.publish...), không kiểm tra theo tên vai trò.

09Chiến lược tối ưu tốc độ tải trang

Trang public (danh sách/chi tiết bài viết) là nơi SEO và tốc độ ảnh hưởng doanh thu nhiều nhất — ưu tiên tối ưu ở đây trước.

  • SSR + ISR: trang bài viết/danh mục render sẵn, revalidate theo thời gian hoặc ngay khi publish/sửa bài.
  • Edge cache Cloudflare: cache HTML trang public + asset tĩnh, stale-while-revalidate để không chặn người dùng khi cache hết hạn.
  • Redis cache tầng API: bài viết mới, đếm lượt tải, danh mục — tránh query PostgreSQL lặp lại cho traffic cao.
  • Ảnh: pipeline resize bằng sharp khi upload, xuất nhiều kích thước + WebP/AVIF, lazy-load qua next/image.
  • Giảm JS phía client: dùng React Server Components tối đa, chỉ hydrate phần thật sự tương tác (form bình luận, ví, menu builder).
  • Không proxy file qua backend: presigned URL trỏ thẳng tới R2/S3 sau CDN — backend chỉ ký URL, không stream file nặng.
  • Hạ tầng: nén Brotli/Gzip, HTTP/2-3, index đúng cột hay truy vấn (slug, category_id, created_at), pgbouncer connection pooling, rate limit ở tầng Redis cho endpoint tìm kiếm.

11Môi trường & hạ tầng

Ba môi trường tách biệt để không ai phải sửa lỗi trực tiếp trên site đang thu tiền thật.

Local — máy dev

Docker Compose

  • Toàn bộ service (web, api, postgres, redis) chạy local
  • R2/S3 dùng bucket "dev", SePay dùng sandbox key
  • Seed dữ liệu mẫu, không đụng dữ liệu thật
Staging — trước khi phát hành

aaPanel · VPS nhỏ

  • 2 vCPU / 4GB RAM, cùng phiên bản OS với production
  • Domain phụ: staging.khomanguon.vn
  • SePay sandbox, R2 bucket "staging" — nơi QA/khách kiểm tra trước khi duyệt
Production — site thật

aaPanel · VPS chính + Cloudflare

  • Tối thiểu 4 vCPU / 8GB RAM, SSD NVMe (Postgres + build Next.js ăn RAM lúc build)
  • Cloudflare proxy phía trước (CDN/WAF/DDoS)
  • SePay production key, backup tự động hàng ngày

Pipeline phát hành

  DEV["Local — Docker Compose"] --> GH["GitHub — pull request → main"]

12Deploy lên aaPanel

Hai cách triển khai trên aaPanel — chọn theo cấu hình VPS thực tế của bạn.

Giả định: VPS chạy Ubuntu 22.04, đã cài sẵn aaPanel, có quyền root/sudo qua SSH. Nếu VPS của bạn khác (CentOS, đã có site khác dùng chung cổng 80/443…), báo lại để tôi điều chỉnh câu lệnh.

Cách A — Docker Compose qua aaPanel khuyến nghị

Dùng lại đúng Dockerfile/docker-compose.yml đã build ở môi trường dev — tránh lệch môi trường. Cần VPS tối thiểu 4GB RAM.

Cài aaPanel & khoá panel

Chạy script cài chính thức từ aapanel.com. Sau khi cài xong: đổi cổng panel mặc định (8888), bật xác thực 2 lớp, đổi URL panel ngẫu nhiên.

Cài Docker Manager từ App Store

Vào App Store → Docker Manager (kèm hỗ trợ Compose) và cài đặt. Nginx thường đã có sẵn theo LNMP mặc định.

Đưa mã nguồn lên server

Qua SSH hoặc File Manager của aaPanel:

# SSH vào VPS cd /www/wwwroot git clone https://github.com/<org>/khomanguon-v2.git cd khomanguon-v2

Tạo file secrets production

Tạo .env.production ngoài tầm truy cập public (quyền 600), chứa DB password, JWT_SECRET, R2/S3 Access & Secret Key, SEPAY_API_KEY, SEPAY_WEBHOOK_SECRET. Không commit file này vào Git.

Deploy bằng Compose

Trong app Docker của aaPanel, chọn Compose → Add, trỏ tới docker-compose.prod.yml. File này chỉ bind cổng ra 127.0.0.1, không public cổng container ra ngoài:

services: web: build: . env_file: .env.production ports: ["127.0.0.1:3000:3000"] restart: always api: build: ./apps/api env_file: .env.production ports: ["127.0.0.1:4000:4000"] restart: always postgres: image: postgres:16 volumes: ["pgdata:/var/lib/postgresql/data"] restart: always redis: image: redis:7 restart: always volumes: pgdata:

Tạo site & reverse proxy trong aaPanel

Website → Add site với domain khomanguon.vn (không cần PHP). Vào site vừa tạo → Reverse Proxy → thêm 2 proxy:

location /api/ { proxy_pass http://127.0.0.1:4000/; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; } location / { proxy_pass http://127.0.0.1:3000/; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header Upgrade $http_upgrade; # cho WebSocket (ví realtime) proxy_set_header Connection "upgrade"; }

Bật SSL

Tab SSL của site → Let's Encrypt → chọn domain → Apply → bật "Force HTTPS". Miễn phí, tự gia hạn.

Nối Cloudflare

DNS record A trỏ về IP VPS, bật proxy (mây cam) để có CDN/WAF/chặn DDoS lớp mạng. SSL mode ở Cloudflare đặt Full (strict).

Khoá firewall

aaPanel → Security: chỉ mở 80, 443 và cổng panel đã đổi. Đóng hẳn 5432 (Postgres), 6379 (Redis), 3000, 4000 khỏi Internet — vì đã bind 127.0.0.1 nên mặc định không lộ, nhưng vẫn nên chặn tường lửa ở tầng OS/nhà cung cấp VPS để chắc chắn.

Đặt lịch Cron

Cron trong aaPanel: (1) huỷ giao dịch SePay "pending" quá 30 phút, (2) dọn log presigned URL hết hạn, (3) backup PostgreSQL hàng ngày lúc ít traffic (VD 3h sáng).

Cách B — Native (không Docker) VPS RAM thấp < 2GB

Nhẹ hơn nhưng dễ lệch môi trường dev/prod hơn — chỉ chọn khi VPS không kham nổi overhead Docker.

  • App Store cài Node.js Version Manager + PM2 Manager (chọn Node 20 LTS), PostgreSQL, Redis — cả ba chạy trực tiếp trên host thay vì trong container.
  • Build rồi chạy qua PM2: pm2 start ecosystem.config.js với 2 tiến trình web (next start -p 3000) và api (node dist/main.js, cổng 4000).
  • Reverse proxy Nginx trong aaPanel cấu hình giống hệt Cách A (proxy_pass tới 127.0.0.1:3000 / :4000).
  • PM2 tự restart khi crash (pm2 startup + pm2 save) — tương đương restart: always của Docker.

13Go-live & vận hành

Checklist trước khi mở cho người dùng thật

DNS & SSL — domain trỏ đúng IP, https hoạt động, http tự redirect https.
Secrets production — đã đổi toàn bộ key sandbox (SePay, R2/S3) sang key thật, không còn key dev trong .env.production.
Test nạp tiền thật — chuyển khoản số tiền nhỏ qua SePay, xác nhận webhook cộng đúng $P và đúng người.
Test tải file thật — mua 1 link trên bucket R2/S3 production, xác nhận trừ tiền đúng, presigned URL tải được và hết hạn đúng TTL.
Backup đã kiểm chứng — chạy thử restore từ bản backup PostgreSQL ít nhất 1 lần, không chỉ tin vào việc "cron đã chạy".
Firewall & panel — cổng quản trị aaPanel đã đổi khỏi mặc định, 2FA bật, các cổng DB/Redis không lộ ra ngoài.
Giám sát — Sentry nhận được lỗi test, Uptime Kuma/monitor báo trạng thái site đúng.
Kế hoạch rollback — giữ lại image/tag bản trước; nếu lỗi nghiêm trọng, docker compose up -d lại tag cũ trong vài phút.

Nhịp vận hành sau khi lên hàng

  • Hàng ngày: xem dashboard doanh thu/lỗi webhook SePay, kiểm tra job backup đêm qua chạy thành công.
  • Hàng tuần: thử restore backup ngẫu nhiên 1 lần, rà soát log lỗi Sentry chưa xử lý.
  • Hàng tháng: vá bản vá bảo mật OS & aaPanel, xoay vòng (rotate) JWT secret hoặc key R2/S3 nếu nghi ngờ rò rỉ.
  • Khi có sự cố thanh toán: đối soát thủ công qua bảng "Giao dịch nạp gần đây" (wireframe #08) trước khi liên hệ SePay hỗ trợ.
